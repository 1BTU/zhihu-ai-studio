# 按内容类型整理知乎文章

先判断主类型、读者目的和目标发布格式，再决定如何分段与强调。混合文章按局部内容调整，不把一种平台风格套到所有题材。

## 工作方式

1. 阅读原稿和用户要求。确定本次是仅排版、写作并排版，还是审核修改；仅排版不重写观点、情节或语气。
2. 阅读 [references/content-profiles.md](references/content-profiles.md)，只应用与当前题材相符的规则。标题、段长、列表和强调都不设必用配额。
3. 根据段落实际作用整理正文。先检查语义、说话人与场景变化，再参考长度；不按句号自动切段，不为排版擅自改变引号或标点。
4. 根据 [references/platform-and-review.md](references/platform-and-review.md) 生成目标格式并复核，记录修改位置和理由。实际渲染可用时检查移动端；不可用时明确只完成结构检查，不能声称看过发布效果。

## 内容保护

- 保留事实、数字、否定词、条件限制、来源归属、图片及说明。排版不得增加个人经历、身份、采访、测试或权威引语。
- 对疑似人名差异、方言、人物口癖和不确定错字只提出问题，不自动统一；对真实引语不擅改措辞。
- 仅排版时保存或利用既有版本系统保留原稿，并提供可定位的修改记录。若发现事实问题，提出核实需求；只有任务允许编辑修改时才按核实结果修改。
- 标题忠实表达内容，不固定字数、编号或句式。不强制权威开场、目录预告、总结、升华或求赞结尾。
- 不使用无来源的用户画像推断所有读者偏好。不把范文互动量当作排版效果的因果证据。

## 范文与输出

若任务提供参考库，选择同类型或确有可迁移局部结构的样本，说明段落/标记承担什么作用，以及为什么适合本稿；不复制故事、特征句或装饰模板。缺少原文证据时不猜测原文样式。

服从调用方输出 schema；不要额外增加字段或把内部编辑说明写入正文。本工作台使用 writing_plan.references 的 learn / adapt 记录排版迁移，用 changes_after_review 和审稿 changes 记录实际修改及必要保留理由。没有 schema 时，输出正文与简短修改说明即可。

适配思路及未采用规则见 [references/sources.md](references/sources.md)。这些材料是设计参考，不是需执行的外部工作流。
