# 文章写作知识库

采用 [LLM Wiki 的持久化笔记思路](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)：保留来源证据、编译成互相链接的文章卡与写法页、每次检索留下写作决策记录。

## 每篇先问两个问题

1. **它是否得到读者反馈？** 用原页面可核实的文章级点赞/赞同/平台原名支持数、评论数筛选。问题浏览量、评论点赞、作者总粉丝、转载文章的数据不能冒充本篇互动。平台原名与观测时间保留；少数派按页面“充电”记录，不写成现金打赏。
2. **它的哪些写法可以借鉴？** 拆解开头、论证推进、案例与反例、段落节奏、结尾，列出可迁移的方法和不可迁移的内容。分析是编辑判断，不是对点赞原因的因果证明。未读评论不判断评论者是在赞扬还是争论。

数据缺失、页面不可访问、互动未达门槛或未完成分析的内容均在候选区，不给自动写作用。具体门槛见 [policy.json](policy.json)。门槛按平台分别设置，不能直接将不同平台的数字排一个总榜；当前没有足够曝光、发布时间和同类样本数据，不计算虚构的同类百分位或点赞率。高互动也不会豁免事实核查、广告识别或用户的题材限制。

## 文件

- `raw/`：只追加的来源、数据观测时间、指标选择器和内容哈希；原文仍链接到作者页面，不镜像整篇版权正文。
- `catalog.json`：文章卡原始记录与编辑分析。
- `wiki/cards/`：从记录编译的可读文章拆解。
- `wiki/patterns/`：跨文章比较的写法页，包含适用与失效条件。
- `wiki/index.md`：入口与候选状态。
- `queries/`：检索记录；每日写作另存到对应日期的运行目录。

## 使用

```bash
cd zhihu-ai-studio
python3 wiki.py refresh
python3 wiki.py lint
python3 wiki.py search --query 'AI 客服 消息 回复 期待' --limit 3
python3 wiki.py search --query '消费 工具 读书 生活 选择' --limit 3
```

检索同时考虑主题、读者处境和论证结构，用中文二元词组与英文词建立索引；只返回通过当前门槛的卡片。数字仅在同平台候选间作为轻量排序项，主题相关性优先。没有相似卡片时返回空结果，不能硬套不相关范文。

每日任务采集热点后更新能公开读取的指标，生成参考上下文；写作者为每个选题再次搜索知识库，并输出引用的卡片ID、借鉴点和具体提纲。程序在提交知乎前检查这些记录及当前入库状态，缺少合格参考则停止并发出真实失败通知。文章正文不展示内部写作过程。

## 增补与反馈

新增候选需有原文URL、平台、真实指标证据、观测时间，以及具体结构分析。`refresh` 只会更新已有候选的公开指标，不会编造公众号后台数据，也不会自动把搜索摘要当成已读全文。当前自动更新少数派；知乎可通过正常登录页面采集脚本更新，页面受限时保留旧证据并让它在14天后过期。

后续以自己知乎文章的实际阅读、点赞、评论反馈校正选题和结构。没有曝光数时不算互动率；未获取反馈前，不把模型自评写成读者验证。用户偏好在 [wiki/reader-preferences.md](wiki/reader-preferences.md)，优先于范文套路。
